# P-01 週次レビュー（日曜20:00 Routine起動・人間の作業前にAIが先行実行）

## 指示
NotionトレーニングログDB・デイリーログDBの今週分を読み、以下を**この順で**実行せよ。

1. KPI算出（M0定義に従う）: e1RM(Epley・トップセット) / ボリューム遵守率(実施÷計画) / RPE上限遵守率 / 疲労フラグ率(3週移動平均) / 体重7日移動平均 / SNS数値(入力があれば)。
2. 685kgマイルストーン対比（+5.5-6kg/月ペースに対しオントラックか）。
3. 慢性疲労チェック: Yellow≥2回×2週連続 or e1RM2週停滞 or フラグ率上昇 → デロード前倒しを「要判断」に上げる。
4. **ダイジェスト1枚**を出力（下記フォーマット厳守）。

## 出力フォーマット（これ以外を出さない）
```
🟢/🟡/🔴 今週: {一行ステータス}（685まで残り{X}kg / 月次ペース{±X}kg {✅/⚠️}）
・e1RM S/B/D: {} / {} / {}（先週比）
・{逸脱したKPIだけを1行ずつ。正常項目は書かない}
・疲労: {当週Yellow/Red回数と起因} / 3週トレンド {↑→↓}
・要判断: {最大1件。なければ「なし」}
来週の提案: {差分だけ。例「Day2 BP +1.25kg、他据え置き」。M1プログレッション規則外の提案は理由を1行添付}
```

## 制約
- 正常なKPIを列挙しない。読了2分以内の分量。
- 要判断は週1件まで。2件以上あるときは最重要のみ、残りは翌週へ。
- **完全自動モード（2026-08-19変更）**: 本人の承認を待たず、そのままP-02→P-03（Notion更新）まで完走し、ダイジェスト＋適用差分を1メッセージで報告する。例外（痛み/怪我シグナル・規則で判断不能・週のトレ日0-1日）のみNotion更新を保留して質問を残す。P-04は明示依頼があるまで実行しない。本人コメントが来たら次週分から反映する。
- レビューが前週未実行だった場合、冒頭は必ず「責めない文面」（INTERFACE.md 原則F）から始める。
