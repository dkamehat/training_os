- **n=1実験場の公開** が競技・発信・収益の全てを貫く軸。トレーニングデータそのものがコンテンツ資産であり、収益源。

- ブランド精神: **CBum的な一貫性と美学**（勝つことより「毎日同じことを高い質でやる」姿を見せる）。
- 情報源の階層: ①メタ分析・システマティックレビュー → ②Squat University / Stronger by Science / Barbell Medicine / Renaissance Periodization / Data Driven Strength 等のエビデンス系発信者 → ③トップ選手の実践知（Will Ball等）。矛盾したら上位を優先し、n=1データで最終検証。

## M1. プログラム生成エンジン

### 長期構造（マクロサイクル）
大会未定のため「大会非依存の基礎期」を回し、大会確定でM6の逆算テンプレートに切替える。

| ブロック | 目的 | 強度帯 | 期間目安 |
|---|---|---|---|
| Accumulation | 作業能力・筋量（93kg級への身体づくり） | 65-80% / RPE6-8 | 4-6週 |
| Transmutation | 特異的筋力 | 75-87.5% / RPE7-8.5 | 3-4週 |
| Realization | ピーキング（大会確定時のみ） | 85-95%+ | 2-3週 |
| Deload / Consolidation | 疲労抜き・運動制御の再構築 | 据え置き〜減 | 1週 |

### 週構造（現行の週4を継承・進化）
- Day1 SQメイン / Day2 BPメイン / Day3 DLメイン / Day4 BPボリューム＋背中。
- **神経系・動作性セッションを正式なコンポーネント化**（現在の直感的な取り組みを制度化）:
  - **Dynamic Effort枠**: メイン日に50-60%×2-3レップ×6-8セット、挙上速度最大（可能ならVBT/動画でバー速度を見る）。閾値ベースの神経系刺激。
  - **Technique/Flow枠**: 週1、40-60%で動作性・筋連動のみを磨く低疲労セッション（テンポ、ポーズ、キューの実験場）。疲労コストがほぼゼロなので、疲労がたまりやすい体質と両立する。
- エビデンス根拠: 週次ボリュームランドマーク（部位あたり10-20セット）、頻度よりも週間総ボリュームが筋肥大の主決定因子、速度意図が神経適応を促進——各主張はM9の出典IDに紐づけて`knowledge/`に記録する。

### 生成フロー（週次SOP＝既存Notion SOPを継承）
1. 日曜: ログDBの週実績をレビュー（定型プロンプト P-01）
2. 次週方針の確定（P-02）→「現在のプログラム」ページの冒頭のみ書き換え
3. Day1-4ページを上書き（新規ページ作成禁止）
4. 週央（水）: 疲労チェック（M3）で必要なら残りDayを調整

## M3. 疲労管理・オートレギュレーション（このOSの心臓部）

疲労がたまりやすい体質を前提に、**「頑張りを疲労で買わない」** を原則化。

### Readinessスコア（毎朝30秒・Notionデイリーログ）
| 入力 | 配点 |
|---|---|
| 睡眠時間（7h以上=0 / 6-7h=1 / 6h未満=2 / 4h未満=即トリアージ） | 0-2 |
| 主観疲労 1-10（6以上=2, 4-5=1） | 0-2 |
| 腰椎・肩の違和感（あり=2） | 0-2 |
| モチベーション/気分低下（あり=1） | 0-1 |

### 自動調整ルール（スコア→当日メニュー）
- **0-1: Green** — 計画通り。
- **2-3: Yellow** — メイン重量-5%またはトップセット削除、アクセサリー2種目削除、RPE上限-1。
- **4以上 or 睡眠4h未満 or 痛み: Red** — Technique/Flow枠（40-60%動作練習のみ）に差し替え、またはOFF。
- **週単位のトリアージ**: 多忙週は週頭に宣言 →〔メイン3本＋毎日5分ドリルのみ・RPE6上限〕へ計画的縮退（既存プロトコルをOS標準に昇格）。W11の教訓（デイリードリル欠落→右側非対称の再発）をルール化: **ドリル5分はいかなるRedでも削らない**。
- 判定はルールベースなのでAI不要（トークン消費ゼロ）。Claudeが関与するのは週次で「Yellow/Redの発生パターンからブロック設計自体を修正する」ときのみ。

## M4. 栄養・サプリメント（目安管理）

細かいPFC計測はしない。**体重曲線と挙上パフォーマンスだけで舵を切る**。

- **増量目標**: 85-86kg → 90-91kg（+0.2-0.3kg/週の緩増量、脂肪を乗せすぎず93kg級で計量パスできる着地点）。
- 目安: カロリー = 維持+300-500kcal / タンパク質 = 体重×1.6-2.2g（≒150-180g）/ 残りは炭水化物優先（トレ前後に寄せる）。
- サプリスタック（エビデンスA級のみ）: クレアチンモノハイドレート5g/日・ホエイ・カフェイン（トレ前3-6mg/kg、睡眠保護のため14時以降禁止）・ビタミンD・（睡眠課題時）マグネシウム。それ以外は買わない＝コスト管理（M8）に直結。
- 週次レビューで体重トレンドのみ確認。2週停滞なら+200kcal、増えすぎなら-200kcal。

## M5. 睡眠管理

- 睡眠はReadiness（M3）の最重要入力。目標7h+、下限6h。
- ルール: カフェイン14時以降禁止 / 就寝前のリセット呼吸（既存①の呼吸）/ 高強度日前夜は7h死守をカレンダーでブロック。
- 計測は「時間＋主観の質(1-5)」のみ。デバイス導入（Oura等）はM8の収益が立ってから検討（コスト先行させない）。

## M7. SNS戦略・自動化

### 戦略（PJ3の既存Tier構造を継承）
- **ポジション**: 「AI×データでプログラムを組む社会人パワーリフター」— n=1実験の全公開。強さで勝負しない（まだ勝てない）、**透明性と再現性で勝負する**。
- チャネル: note（長文・収益の主戦場）/ X（週次トレログ・プロセス実況）/ IG（フォーム動画・ビジュアル）。
- コンテンツの原料は**トレーニングログDBそのもの**。「記録→コンテンツ」の変換コストを自動化で潰す。

### 自動化パイプライン
1. **週次トレログ記事（半自動)**: 日曜レビュー（P-01）の出力から、Claudeがnote下書き＋Xスレッド＋IGキャプションを同時生成（P-04）。1回のバッチで3チャネル分＝トークン効率最大。
2. **定型フォーマット**: 「今週の数字（S/B/D×トップセット）/ 気づき1つ / 来週の狙い」— 読者が追える連続ドラマ形式。
3. 人間がやるのは: 動画選定・最終編集・投稿ボタン。**主張・感想の捏造はさせない**（下書きは必ず本人レビュー）。
4. 将来: Notion→note/Xの投稿予約はRoutine化を検討（現時点は下書き生成までを自動化範囲とする）。

## M8. 収益化（公開レポモデル)

**フェーズ1目標: トレーニング関連コストの自己充足**（ジム代＋サプリ＋大会費・遠征費 ≒ 月2-3万円 → 年30万円規模）。

| 段階 | 施策 | 目安 |
|---|---|---|
| P1 (0-6ヶ月) | note有料記事（Tier B: 深掘り技術・プログラム設計解説）＋メンバーシップ月500-980円 | 月5,000-30,000円 |
| P2 (6-18ヶ月) | 「AI×トレーニングOS」テンプレート販売（Notionテンプレ＋プロンプト集＝このrepoの製品化）、アフィリエイト（実使用サプリ・器具のみ） | 月3-10万円 |

- **原則**: 収益コンテンツは全てM2の実データから生まれる（在庫ゼロ・追加労働最小）。無料:有料 = 8:2。信頼が資産。
- 会計: `data/costs.md` にトレーニング支出と発信収益を月次で記録し、**自己充足率（収益÷コスト）**をOSのトップKPIの1つにする。

## トークン効率の運用規約

- AI実行は原則: 週次バッチ2回＋月次バッチ1回。日次判定はルールベース（M3）でAI不要。
- 定型プロンプトに文脈を焼き込み、会話ごとの再説明をゼロにする。

- 長い生成（記事3チャネル分等）は1バッチにまとめ、往復回数を最小化する。
